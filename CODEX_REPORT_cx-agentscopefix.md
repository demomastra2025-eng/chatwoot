## Что изменено и что сохранено

- Все встроенные tool ID, которые реестр объявляет для агентской области, снова доступны для валидации ссылок. Сохранённые описания агентов с такими ссылками можно редактировать и сохранять. Ссылки из описания снова попадают в runtime набор при включённых соответствующих функциях и интеграциях; это проверяется в `assistant_spec.rb`.
- Проверки пациента остались на этапе вызова в `enterprise/lib/captain/tools/agent/patient_scope.rb`. Инструменты без безопасного правила привязки к пациенту возвращают прежний нейтральный `record_not_available`, а `enterprise/lib/captain/tools/agent/patient_scope.rb:200` публикует событие отказа только с ID аккаунта, разговора и контакта, именем инструмента и видом ID. Аргументы отказанного вызова не передаются в аудит.
- Для сообщений разрешён текущий разговор. Чужой разговор, межканальная адресация, прямые вложения из общего аккаунта и артефакты без токена документа ассистента отклоняются до вызова сервиса. Для операций с сообщением проверяется принадлежность сообщения текущему разговору. Справочник полей задач оставлен доступным как конфигурация клиники.
- Поведение staff Copilot, проверки доступа к своим записям, нейтральный ответ и событие отказа сохранены. Миграций, операций удаления данных и новых зависимостей нет.

## Что ещё может потребовать решения

- Без запуска RSpec нельзя подтвердить создание задачи и отправку заметки через реальные модели и callbacks. Новые тесты проверяют эти пути; возможный сбой нужно вернуть в эту ветку.
- Встроенные ссылки совместимы при сохранении описаний, но часть ранее доступных операций (поиск задач и компаний, существующие задачи, напоминания, интеграционные записи и слияние контактов) теперь отвечает нейтральным отказом при вызове. Для них нет подтверждённого правила владения записью пациентом. Вопрос владельцу: какие из этих операций следует разрешить и по какому проверяемому отношению к текущему контакту?
- Прямые вложения и межканальная отправка через `send_message_to_conversation` ждут правила проверки источника файла и адресата для пациента. Документы ассистента с проверяемым токеном остаются доступными.
