# Подтверждённые формы MedElement

Источник: проверка тестовой организации владельцем 07.10.2026. Это описание наблюдённого API, без идентификаторов врачей и учётных данных. Генерируемый `SHAPES.md` из `medelement:capture_samples` теперь также содержит этот контракт.

## Врачи

`GET /v1/timetable/get_specialists` вернул HTTP 200 и объект, ключом которого служит код врача. Внутри были `specialistCode` (число, возможны значения больше точного диапазона чисел JavaScript), `isSchedulePublished` (число `1`, хотя документация называет поле Boolean), `userName`, `receptionTime` (число минут), `cabinets[]` с `companyCabinetCode` (строка), `cabinetName`, `cabinetType` (число), `cabinetNumber` (строка). У всех трёх проверенных врачей было `isSchedulePublished=1`; значение `0` не наблюдалось. Признаков пагинации, полноты ответа, увольнения или отключения врача нет. Код врача в приложении хранится и сравнивается как строка.

## Диапазон расписания

`GET /v1/timetable/get_timetable` принимает `date[0]`, `date[1]` и ровно один `specialistCode`. Интервал включителен: запрос 07.10.2026–10.10.2026 вернул четыре ключа формата `dd.MM.yyyy`. Без `specialistCode` сервис ответил HTTP 400 «Не правильно передан код специалиста». Общего запроса для всех врачей нет. Рабочие интервалы были получены на горизонте +90 дней.

| Вид дня | Наблюдённая форма | Решение теневой синхронизации |
| --- | --- | --- |
| W, рабочий | Непустой `timetable[]` с `{start,end,working:boolean}`; `clinicWorkingHours` и `specialistWorkingHours` — объекты со временем начала и конца | Подтвердить только при корректных рабочих интервалах и порядке часов |
| D, выходной | Пустой `timetable[]`; `specialistWorkingHours` — строка `"day off"` | Первое наблюдение оставляет старые интервалы; второе подряд подтверждает пустой день |
| P, пустой | Пустой `timetable[]`; `specialistWorkingHours` — объект часов | Оставить день непроверенным и сохранить прежние интервалы |
| Аномалия | `specialistWorkingHours.start` в 08:00, `end` в 00:00 той же даты; `clinicWorkingHours` 00:00–00:00 | Оставить день непроверенным; это не доказательство отпуска или выходного |
| Отсутствующий ключ/другая форма | В ответе нет ключа даты либо невалидная структура | Оставить день непроверенным и сохранить прежние интервалы |

`working=false` означает нерабочий интервал, а не занятую пациентом запись. `time_off[]` содержит интервалы отсутствия `{start,end}`; `start_lunch` и `end_lunch` обозначают обед. Их можно сохранить в хеше исходного дня, но нельзя превращать в рабочие интервалы без отдельного продуктового правила.

`by_update_date` возвращает приёмы и после изменений может показывать пустой массив с задержкой. Это не сигнал об изменениях расписания. Лимит запросов в секунду и `Retry-After` не задокументированы; один ответ HTTP 429 раньше наблюдался, но не воспроизведён в этой проверке.
